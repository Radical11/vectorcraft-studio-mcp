# Progress and stage comparisons

**15 October 2026:** ten of eighteen attempts are accounted for; eight remain deferred. Four passed final construction review, one delivered files with unresolved acceptance, one retained partial artwork, and four were disrupted without final artwork.

The work has progressed from an existing designer workflow to isolated native roughs, focused task/stage acceptance, and explicit relationships between meaningful parts. These capabilities are implemented and technically tested. Their comparative design benefit remains unestablished.

## How to read the evidence

### Simple names and step numbers

**Standard**, **Layout first**, and **Full process** are the three study profiles. **Focused build** is an available profile outside these three study arms. Exact configuration IDs remain in the [process guide](../PROCESS.md#choosing-a-profile).

An attempt reads **Repair · Full process · Run 1**. **T07** is its stable short reference from the frozen trial order; **T07.10** is its tenth recorded capture. Run 2 is another attempt, not a later version of Run 1. Original trial IDs and version names remain alongside the descriptions and in the webpage's source details.

| Reading label | What this stage does | What counts as progress |
| --- | --- | --- |
| Try layouts | Explore distinct native roughs | Learn which idea communicates or exposes a weakness; alternatives need not get better in sequence |
| Test a detail | Build one difficult part separately | Observe whether the contact, silhouette or text works before transferring it |
| Arrange the scene | Establish placement, scale and reading order | Fix a concrete spacing issue or explicitly accept the existing arrangement |
| Set the text | Check exact wording, live text, fonts and readability | Correct clipping or placement, verify unchanged text, or explain a wordless brief |
| Build the drawing | Construct forms and their critical interactions | Make an observed contact clearer while preserving its neighbors |
| Polish and check | Inspect the whole result and production readiness | Resolve consequential defects or verify a preserved result; grouping alone need not change the image |

Every available step has a short name, a **change / check**, the stage's **purpose**, its **recorded observation**, and an explanation of **how to read the progress**. The editorial captions in [STEP-GUIDE.json](STEP-GUIDE.json) bind to capture IDs and full-image hashes; they summarize existing observations rather than introduce new reviews.

### What gradual improvement actually looks like

- **Book exchange · Standard · Run 1, T02.02 → T02.03:** NIGHT clips in the first text capture, then becomes fully visible after a frame and spacing correction. This is an observed local fix.
- **Repair · Full process · Run 1, T07.10 → T07.11 → T07.12:** opening the tyre edge introduces duplicate spokes; cleanup removes those artifacts; whole-scene inspection and final reviews follow. The first correction fails before the next passes.
- **Library guide · Layout first · Run 2, T10.08 → T10.09:** later frames and search spacing do not win a preference over the earlier result. Both reviewers judge equal; T10.08 stays retained and quality acceptance stays unresolved.

Progress therefore includes learning, correction and verification. These examples do not establish that a newer profile produces better designs overall. See [how the implementation developed](../PROCESS.md#how-the-implementation-has-developed) for the separate history of workflow changes.

Follow an attempt from its available roughs through composition, typography, imagery, finishing, and corrections. Captures preserve the original order and confirmation status. A later version is not automatically better; the retained best can be an earlier version. Some stages have multiple captures and some have none.

Cross-profile views group the same brief **and repeat**. Missing slots remain visible. Different repeats are separate attempts and are not substituted to create complete pairs. These are descriptive side-by-side displays, not newly collected preference results.

Stage captions identify the existing record they summarize. They do not add new aesthetic scores or independent reviews. A confirmed image means the recorded capture was confirmed; it does not imply final acceptance. Native reopening and export checks establish file properties rather than communication quality.

The [published research explorer](https://radical11.github.io/vectorcraft-studio-mcp/research.html) supports stage and trial selection with full/intended-size previews. Its [source page](../../site/research.html) also works locally. These displays use existing evidence and introduce no new preference judgments.

The additive [stage supplement](../../public-evidence/process-stages-20261015/README.md) indexes 56 existing captures: 17 roughs, four representative construction studies, and 35 production/correction captures. It does not replace the original checkpoint. Its [publication audit](../../public-evidence/process-stages-20261015/publication-audit.json) discloses the earlier JSON normalization/redaction hash differences.

- Publication creates prior exposure; later owner feedback cannot be described as guaranteed blind.
- Saved-selection recovery, selection-sensitive area-text preflight, and an honest voluntary unresolved-quality stop remain post-study proposals.
