# Experimental native designer process

Status: implemented experimental policy; 15 October 2026 checkpoint accounts for ten of eighteen attempts, with eight deferred. No comparative aesthetic improvement is established. See [research programme](research/README.md) and [calibration record](research/CALIBRATION.md). The historical dated paper remains unchanged.

## Profiles and sequence

`layout-blockout-v1` inherits designer-v1 and adds purpose-driven native studies before production. `designer-process-v1` adds focused task/stage acceptance, meaningful entities, separate spatial and construction graphs, and relationship-aware inspection. Both are full-mode opt-ins. Existing profiles and historical contracts remain available with their former behavior.

Record `design_brief` (audience/message/response/viewing context/medium/production requirements/style/assumptions/locked copy), research and calibration. Record `layout` with three alternatives: ID, concept, reading order, negative space, actual copy and normalized bounds. Each alternative becomes an isolated native study. Use actual fonts and exact copy; roughness is a temporary level of refinement rather than a required faceted final style.

## Native studies

Use `workflow_begin` stage `composition`, plan `context:"study"`, `study_id`, `layout_id`, purpose, changes, expected_result and two or three named observable checks. Native calls then route to a dedicated connection with independent document/revisions/recovery. The production connection remains preserved. The five-tool interface is unchanged; no generic document-switch exception is opened for older profiles.

The study packet exposes that batch's goal/checks and its own full/use evidence, preview context and current/uncertain flags. Before a capture, current images are absent; after further edits they are stale. Uncertain study operations require recovery inspection without replay. After explicit assembly start, the selected blockout supplies the initial production preview, bound to document/spec revisions. It does not accept a production task or stage.

Capture through `workflow_checkpoint`. Actually inspect both returned images. Confirm `pass`, `revise` or `blocked`, exact `check_results`, observations, and designer image-action evidence. Use `close_study:true` for a passed study or an explicitly abandoned blocked study. A revise requires another correction batch; it cannot close as passed. Record `blockout` with the closed passed study ID. Three current observed native blockouts precede directions and fresh independent concept selection. Inapplicable checks need reasons. The gateway authenticates artifacts and ordering, not the truth of a host image assertion.

Resume the parent run from a fresh connection: both saved contexts are restored separately. Uncertain study edits block the study only and are never replayed. A study cannot contribute object IDs or stage acceptance to production. Closing/shutdown affects only connection-owned documents/windows.

Record selected target/spec using the existing contracts, then `assembly` action `start` and selected `study_id`. This explicit transition opens the selected immutable blockout in production before edits. IDs are subsequently reconciled against actual production captures. The native study is the primary target; optional host-generated feature/style studies do not replace final live text or editable vectors.

Direction IDs must match the current three layout IDs. Each thumbnail must contain the same bytes as its matching observed native blockout preview. Fresh concept review covers both full and intended-size images for all registered blockouts, plus calibration references. These links prevent an inspected study from standing in for an unrelated proposal; they do not prove that a proposal is visually successful.

Directions actual_copy must cover every native live-text string in the matching blockout, normalizing whitespace for wrapping. This checks actual text coverage rather than trusting intended copy alone; additional explanatory prose is not automatically classified as rendered text. Optional unregistered studies cannot replace registered direction evidence. Wordless studies retain the inherited explicit no-copy description.

## Meaningful construction and relationships

The full profile records `entity_graph` after transition: entities have `id`, current `spec_id`, explicit working/supporting role, optional parent and named anchors normalized against native bounds. `dependencies` are prerequisite/dependent pairs and must be acyclic; spatial relations may contain cycles. Split only when useful. Shared style and a single owner for each interaction prevent unrelated fragments from drifting apart.

Roles, useful decomposition and interaction ownership are host policy. The gateway validates declared graph structure; it does not automatically discover parts, schedule every dependency, or solve semantic attachments. Their intended visual benefit remains a hypothesis for the matched pilot.

Production uses the existing four stages and focused tasks. Construct focal relationships first, supporting context next and visible detail last. Preserve inherited representative construction studies, three final correction rounds, independent retained-best selection and all production checks.

Record `relation_check` against a current confirmed production version. Map every graph entity to real native IDs and inspect full/use/target images. Supported geometric diagnostics: `anchor_distance` with named endpoints and an explicit tolerance; `alignment` with endpoints, tolerance and x/y axis; `containment` based on native bounds. Bounds/anchors are proxies and never prove meaningful contact. `contact`, `grip`, `association` and `occlusion` require actual observed judgments. Every relation needs pass/fail/not_applicable and visible observations; N/A needs a reason. Failed geometry cannot be attested as passing.

A failed relationship queues a consequential focused correction. Native changes invalidate incident relationships using entity fingerprints including ancestry and order. Unmapped/unknown impact conservatively invalidates all relationships. Target/spec changes stale all checks and require the graph to be reconciled. Whole-scene acceptance remains necessary: selective checks do not guarantee that unrelated edits preserve visual meaning.

Preflight requires closed studies, explicit production transition, current accepted stages and current resolved relationship evidence. Export bytes, exact copy, native editability and actual inspection retain their existing requirements. Stage, relation and export checks are distinct. No geometry count, hash or graph size is an aesthetic score.

## Trust and limits

Five tools enforce state, bytes and revisions. The host provides semantic grouping, scope declarations and honest observations. Arbitrary native commands cannot be restricted perfectly to a semantic region. A passing model critic is not human approval; separate fresh model contexts are not independent human experts. The current programme evaluates the complete method as a bundle and does not attribute all effects specifically to graphs.
