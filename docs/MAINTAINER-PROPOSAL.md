# Draft proposal — not sent

Proposed title: Community companion for research-to-vector design intent and independent visual critique

I built VectorCraft Studio, an unofficial Codex-on-Windows companion, to address a design-workflow problem: research and art direction can become disconnected from actual native construction. Merely documenting a plan or passing layout checks does not ensure the illustration communicates the intended idea.

The companion keeps VectorCraft's native MCP instructions, resources, prompts and commands. A standard-library Python gateway adds five workflow tools and project-local version-three records: brief/research, inspected reference calibration, developed alternatives, independent concept review, target/spec, representative construction pilot, staged full/use-size inspection and two specialist final critiques. Native objects/live text remain editable. The strongest common-brief artwork can be the original; target matching alone never establishes improvement.

Installation configures only VectorCraft's Codex section and two owned skills, with explicit executable/vault paths, fresh-home support, private snapshots and conflict-aware rollback. The engine remains separately installed. Local Windows tests exercise native passthrough, desktop ownership and interrupted-operation recovery; hosted CI covers fixtures, installer transactions and packaging only.

Reproducible example: use the locked campus-poster brief in benchmarks/briefs31, inspect the source/review protocol in docs/EVALUATION.md, then open the selected native artwork and live-text SVG from the showcase. A small-edit example changes one native fill through quick mode without research. The release package includes checksums and a clean-checkout installation check.

The independent comparison gate completed, and the owner preferred the retained Studio versions in all three anonymous pairs. Results remain limited case-study evidence, not a claim of professional superiority. The case studies are creator-authored comparisons rather than randomized independent-agent trials. Remaining limitations include subjective agent-attested image judgments, variable host capabilities, limited reference coverage and simplified generated-reference texture/anatomy.

Local results available for review: 124 checks passed against the documented Windows installation, including native passthrough and recovery. Actual install/rollback/reinstall preserved unrelated settings. Two fresh blind reviewers agreed on clear common-brief improvement for the three new locked briefs, with no consequential regression in the selected candidates. The repair illustration still has moderate target fidelity after three correction rounds. Historical comparisons were mixed, including a stronger original infographic and an editorial cohesion regression; no blanket superiority claim is made. These results and the owner's recorded selection are separately recorded in public-evidence.

This contribution is distinct from [agent setup #1064](https://github.com/storytold/vectorcraft/issues/1064) and [CLI discovery #1065](https://github.com/storytold/vectorcraft/issues/1065): those improve distribution/onboarding, while this companion preserves design intent and evaluates finished artwork. It can benefit from those native improvements without replacing them.

Would documentation of, or a link to, the separate companion be useful first? If there is interest, a later discussion could identify small optional native hooks for workflow evidence. I understand [upstream's Rust-only guidance](https://github.com/storytold/vectorcraft/blob/main/AGENTS.md); directly merging the Python gateway is not the initial proposal.
