# Contributing

Keep the companion scope clear: host judgment and workflow enforcement around VectorCraft, not a replacement vector renderer. Make changes in src/ and deployable skills in skills/. New enforcement belongs to version-three designer-v1 records. Preserve legacy helper contracts and historical evidence.

Use Python 3.13. Run self-contained tests before proposing changes; run local Windows integration checks when touching native commands, desktop ownership or recovery. Add tests for consequential policy/installation changes, not tests that merely mirror low-impact prose. Distinguish fixtures from actual observed artwork.

Artwork reviews require fresh independent reviewers who actually inspect images. Report creative weaknesses as well as defects. Profiles should express communication priorities and relevant subject features, never universal style rules. Respect required wording and immutable sources; preserve stronger originals.

Do not commit credentials, Codex configuration, private backups, raw vault contents, historical local runs or third-party assets without redistribution rights. Every distributed asset has a specific ASSETS.md row with author/source/license/notes. Do not include font binaries or upstream trademark artwork. Owned contributions use MIT OR Apache-2.0.

The upstream VectorCraft project has its own Rust-only and clean-room rules. This Python companion is a separate project. The initial maintainer approach proposes documentation/linking, not merging Python into the Rust engine.
