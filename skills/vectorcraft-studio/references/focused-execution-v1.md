# Focused execution v1 contract

Experimental opt-in for new full v3 runs. Default designer-v1, quick mode and historical contracts are unchanged. Research/calibration, developed alternatives, fresh independent concept review, selected target/spec, representative construction study and two final specialists remain required. See workflow_status full schemas for inherited records.

Before an interaction edit, trace each arm/object from its source to its endpoint and name its role in the goal/checks (for example, upper working hand versus lower supporting hand). One group ID may contain several parts; a small ID list does not prove the task is semantically simple. Verify contact and ownership before smoothing a local contour.

Use `workflow_status {view:"working"}` for the compact packet. It gives one current task, relevant last confirmed IDs, full/use preview paths and freshness, available detail images, stage completion checks, unresolved findings, evidence references and the next action. It is a working view, not a reset of the host context. Inspect the actual document before using stale IDs.

`workflow_begin.plan` keeps purpose, changes and expected_result. Add:

- task_id: unique filename-safe ID; reuse only for that unresolved task.
- goal: one component or tightly connected-group visible outcome.
- entities: one to three current specification IDs.
- preserve: specific neighboring/global relationships to retain.
- checks: two or three unique {id,description} observable checks.
- finding_id: first correction-queue item only, required when queue is nonempty.

Do the batch, then capture using the usual checkpoint. Before confirmation actually view full/use previews and target. Confirm with outcome pass|revise|blocked, observations, preservation_observation, cumulative element_map, and check_results [{id,outcome:pass|fail|not_applicable,observation,reason?}]. Provide image_inspection (performed, paths, observations) and image_observation (tool,evidence,observation). An inapplicable check needs a reason. A failed check cannot pass the task. Revise/blocked need a concrete reason and leave the task unresolved while permitting a new correction batch. Later stages and preflight remain blocked. The next task must address the first queued finding; do not replace it with unrelated work.

stage_complete defaults false: an inspected or passing component does not finish the stage. To complete it, explicitly set true and provide stage_checks for all three keys with result/observation/reason fields. All required elements through the stage need real native mappings and no blocking findings may remain.

| Stage | Completion keys |
| --- | --- |
| composition | placement_scale, reading_order, focal_separation |
| typography | exact_copy, live_text_fonts, use_size_readability |
| imagery | recognizable_forms, proportions, critical_interactions |
| finishing | scene_cohesion, visible_defects, production_readiness |

Later-stage details are deferred, not invented as completed. Optional detail_images are absolute project image paths. The gateway stores their bytes; the host must actually inspect relevant crops. No automated perception is claimed.

Edits reopen the affected stage and later stages; preservation observations recheck earlier decisions. Target/spec changes invalidate acceptance/mappings and stale prior tasks. Old findings remain visible for reconciliation against the new spec. Never replay uncertain operations. Resume preserves pending tasks and the queue; no extra review budget is granted.

After stage completion, run normal export/preflight and fresh final reviews. Consequential candidate review findings are queued critical-first while correction remains allowed. Deliver the independently retained best; an original may win. Preserve current roots, originals, native editability, live copy and connection-owned recovery. Arbitrary native commands are not restricted to semantic scope; the packet is guidance and post-edit observations must address scope compliance.
