# Gateway workflow v3

New full runs default to `quality_profile: designer-v1`. Before step 3, record `calibration` with three to five actually inspected references from research. Directions must be developed compositions with actual copy, image treatment and all five copy checks. A fresh `concept_review` binds its judgments to current calibration/direction hashes and chooses a direction. If all are weak, one additional exploration pass is required before proceeding with disclosed limitations. Target and spec carry the chosen direction_id; spec adds construction_method and copy_evaluation. Before imagery, record an actually observed representative native or trace-rebuild `construction_study`, bound to current spec hash/revision, with concrete object maps and full/use-size images. See [designer-v1](designer-v1.md).

For step 8, designer-v1 uses separate fresh communication and craft reviewers, includes retained best and untouched original when different, and records a common-brief winner separately from fidelity. Both specialists assess previously unreviewed baselines; an original may be best_version. Existing runs without quality_profile retain the following legacy contract unchanged. Quick edits and explicit regular VectorCraft remain lightweight. Do not use legacy-v3 to evade substantial-work prerequisites; it exists for compatibility and explicitly labeled evaluation controls.

`workflow_status` returns authoritative schemas and integrity/resume state. Records contain concise decisions and agent-observed image evidence; hashes never prove perception, originality or taste. Project evidence lives under `work/vectorcraft-studio/<id>` inside the authorized project root.

1. Save a project brief and call `workflow_start {mode:"full",brief_path:ABSOLUTE,run_id:UNIQUE,use_width:INTENDED_WIDTH}`. Set use_width from the brief when preserving an original, so comparisons use the same viewing size. Its default is half the original artboard width. Existing artwork is preserved as native/full/use-size original. Document replacement is allowed only before edits/pending batches; use a new connection/run for another document. Copy authorized external assets into the project without widening filesystem roots.
2. Retrieve relevant vault notes, actually view reference artwork, and record kind:"research". Use v2's subject_summary, audience_and_use, synthesis, facts, assumptions, gaps and per-reference observation/transformation/actual image action. Target 15–25 relevant works/four source roles; disclose shortfalls. Legitimate prior studies may be reused only after verifying their evidence/relevance; label historical observations and refresh unstable factual claims.
3. Explore and actually view three distinct thumbnails. Record kind:"directions" with copy_options (empty for locked/no copy), selected and selection_reason. Record kind:"target" with PNG path, method, observation, concrete features and prompt if generated. A vector-study target must guide image/layout decisions, not be a blank placeholder.
4. Record kind:"spec": canvas width/height/use_width, locked_copy, palette, focal_silhouette, reading_sequence and elements. Each element has semantic id, kind, first stage and [x,y,w,h] box. Text adds exact final text/font/size; illustration adds concrete features. copy_rationale explains subject/audience fit. Optional anchor_budget caps tracing complexity (default 30000); intentional_bleed identifies elements allowed outside artboard. Discover engine fonts and use actual copy lengths. Amend target/spec when observed evidence warrants it; this invalidates review readiness.
5. Call `workflow_begin {stage,plan:{purpose,changes,checks,expected_result}}` before edits. Stages: composition, typography, imagery, finishing. Engine aliases, convenience tools, batches and UI authoring are gated. Internal recovery saves/queries remain available. Selection/view commands are available; unknown authoring commands are conservatively gated.
6. `workflow_checkpoint {version:UNIQUE,data:{phase:"capture"}}` saves native, inspection and full/use-size renders. Actually view both and the target. Confirm the same version with phase:"confirm", observations, target_comparison (silhouette,proportions,negative_space,hierarchy,copy,detail), element_map from semantic ids to actual object ids, departures [{element,reason}] and decision. Elements introduced so far must map to existing objects. Confirm before another batch. Quick mode only needs observations/decision.
7. Export SVG, PDF and PNG through this gateway and inspect actual files; record kind:"preflight" with version, files and observations. Full mode checks inspected stages, current document, actual copy/fonts, bounds and expanded vector content. Exports must match their recorded document/spec revision and unchanged bytes. It does not certify subjective readability. Edits/spec changes invalidate preflight. Export matching formats from the same bytes.
8. Record kind:"packet" with version. Give the fresh independent reviewer neutral A/B images, inspections, target, observable requirements and brief plus rubric/reviewer contract. First original comparison needs incumbent_assessment. Record kind:"review" with version, returned review JSON and image_observation {tool,evidence,observation}, only after verifying actual reviewer image actions. Both versions' full/use-size renders and target must be viewed; exclude creator scores/rationale/prior verdicts.
9. If active, plan/inspect corrections and repeat preflight/packet/review. Deliver best_version, not the latest file. Runs stop on pass, two non-improving corrections or three rounds; disclose weaknesses. Record kind:"unavailable" with a precise reason when required inspection/review cannot happen.

Resume with `workflow_start {resume:RUN_ABSOLUTE}` in a fresh connection. It verifies hashes and restores saved recovery/native artwork with pending batches retained. Inspect restored artwork; uncertain operations are never replayed or hidden. A passed run can reopen for newly observed feedback only with `reopen_reason` and a project `feedback_path`, within its original remaining three-round budget. Exhausted or stalled runs cannot reopen; never reset the budget by cloning a run.

Legacy v1/v2 keep `studio_run.py`/`pipeline.py` contracts and history. Those helpers never mark a v3 run reviewed; the gateway owns new v3 state.
