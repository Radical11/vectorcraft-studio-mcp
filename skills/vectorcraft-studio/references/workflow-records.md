# Workflow records and commands

All JSON inputs live inside the current project. The helper copies immutable evidence and checks hashes on `status`. It validates structure and declared tool-use evidence; the calling agent must verify that viewing/editing actions really occurred. It cannot prove authorship, originality or image inspection from JSON alone.

Use installed Python with these scripts. Paths below stand for absolute project/run paths.

1. `studio_run.py init --project-root PROJECT --brief BRIEF --run-id NAME` creates a version-two run. `--legacy` is only for compatibility testing or explicitly choosing the old workflow.
2. `pipeline.py record --run RUN --kind research --file RESEARCH.json --images-verified` requires:
   - `subject_summary`, `audience_and_use`, `synthesis`: nonempty text.
   - `facts`: list of `{claim, source_url}`; `assumptions` and `gaps`: lists, empty when none.
   - `discovery_passes: 1`, `gap_filling_passes: 0` or `1`.
   - `references`: each has `title`, `creator`, `url`, `accessed`, `source_type`, `observation`, `transformation`, and `visual_inspection: {tool, evidence, observation}`. Tool evidence names a real action/source screenshot or displayed-image record, not a fabricated identifier. Below 15 references or four types requires explicit gaps. Zero inspected references prevents research completion; report inability honestly.
3. Record `--kind directions` with `{directions:[{id,concept,metaphor,visual_language,thumbnail}, ...three], selected, selection_reason}`. Thumbnail paths point to project files. Planning SVGs/PNGs are permitted. View them before selection; thumbnails are not final artwork.
4. Record `--kind layout` with text fields `hierarchy`, `focal_point`, `placement`, `spacing`, `typography`, `palette`, `reading_sequence`. Include quantitative specs in the text where useful. Record another layout when it changes; old records remain intact.
5. `pipeline.py begin --run RUN --stage composition --file PLAN.json`, where plan has `purpose`, `expected_result`, `changes`, `checks`. Repeat before substantial batches; stages are `composition`, `typography`, `imagery`, `finishing`. Earlier stages need inspected checkpoints before advancing. Multiple batches in a stage are allowed. During corrections revisit any needed stage.
6. Make planned edits through VectorCraft. Save native and render full/use-size PNGs; save `doc_inspect` JSON. `studio_run.py snapshot --run RUN --version ID --native FILE --images FULL USE --inspection JSON` preserves them. Before changes to supplied input, use `--role original` to preserve it; this exception never establishes research completion.
7. Actually view both saved snapshot images. `pipeline.py checkpoint --run RUN --version ID --file CHECK.json --images-verified` requires `paths` pointing to the viewed full and use-size images (byte-identical source copies are accepted), plus text fields `observations`, `alignment`, `optical_balance`, `readability`, `style_consistency`, `subject_relevance`, `originality`, `decision`. Null criteria are not needed: describe no text when applicable. Checkpoints clear the pending batch and update `working_version`; they don't establish a reviewed best.
8. Export and inspect requested formats. `pipeline.py preflight --run RUN --version ID --file PREFLIGHT.json` requires `required_content`, `export_files`, `font_warnings`, `clipping_and_readability` text and `files`: existing project export paths. Exact checked bytes are preserved. All stages must be inspected and no batch pending. Preflight makes only this working version eligible for final critique.
9. Use existing `packet`, `review`, `status`, `unavailable`, `extend` commands. The first completed candidate uses `--kind initial`; subsequent corrections use `revision`. New edits invalidate review readiness until another preflight. Reviews cannot precede completion. `best_version` is reviewed; `workflow.working_version` is merely inspected.

Original comparison: the first packet includes the preserved original when available. Ask the reviewer to include a full `incumbent_assessment` as described in reviewer.md; its judgment of the original is recorded only at final critique. Original and candidate are scored against the same brief, and ties/regressions preserve the original. No revision budget is spent preserving it.

If an operation times out, `status` verifies evidence and shows a pending batch. Inspect/reopen the real last saved document, then complete its checkpoint or save a corrected snapshot. Do not repeat uncertain edits. If no images/reviewer can be inspected, use `unavailable --reason ...` and disclose exactly which part is incomplete.

Vault commands: `brain.py init`; `brain.py search --query "subject style use"`; `brain.py write --kind sources|principles|styles|projects|lessons --name SAFE-ID --file NOTE.md [--expected-sha CURRENT-HASH] --context "run/decision"`. Default vault is `D:\Design Brain`; `--vault` before the command selects an isolated test vault. Sources cannot be overwritten. Updates require the current SHA; concurrent writer or stale hash failures require re-reading. Do not automatically delete another process's lock.
